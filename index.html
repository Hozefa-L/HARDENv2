Benchmark and Code Release

A reproducible bytecode benchmark for smart-contract vulnerability detection

This repository accompanies the paper A Reproducible Bytecode Benchmark and Empirical Study of Smart-Contract Vulnerability Detectors. It ships CGT-DAppSCAN, a multi-label benchmark of 2,186 Ethereum contracts across ten SWC weakness classes, together with HARDENv2, the heterogeneous-graph model family and the full evaluation pipeline used in the study.

The benchmark data is committed directly in the repository, so a single clone reproduces the paper's numbers. No external download, RPC node, or third-party dataset is required for the main path.

The Benchmark

2,186 contracts merged from the Consolidated Ground Truth and DAppSCAN corpora, with fixed splits, graph tensors, feature tables, and per-label assessment masks.

The Models

HARDENv2 graph transformers with enriched opcode features, evaluated against tree ensembles, MLP and sequence baselines, flat GNNs, and Mythril.

The Finding

Under a fixed bytecode-only protocol, tuned tree ensembles lead the benchmark; the study quantifies where graph structure helps and where it does not.

Get Started

Clone, install the pinned environment (Python 3.12), and confirm the data is intact. The integrity check takes about 30 seconds on CPU. 

git clone https://github.com/Hozefa-L/HARDENv2
cd HARDENv2
pip install -r requirements.txt

python scripts/verify_data.py

A first end-to-end run trains one configuration on one seed in a few minutes, CPU only: 

python -m src.training.run_experiments \
    --config configs/phase7_balanced.yaml \
    --model-variant classical_xgboost --seed 42

The full study trains 14 configurations over five seeds (70 runs) and aggregates them into the paper's tables. The classical baselines run on CPU in minutes; the neural configurations need a single CUDA GPU with 12 GB of memory and finish in roughly a day: 

python -m src.training.run_experiments --config configs/phase7_balanced.yaml
python scripts/level4_analysis.py --manifest reports/phase7_balanced/phase7_run_manifest.json

The Benchmark

CGT-DAppSCAN is a derived benchmark. It merges the Consolidated Ground Truth and DAppSCAN corpora into one masked, multi-label, graph-ready dataset under a single fixed protocol, operating on runtime bytecode only. Labels carry per-(contract, label) assessment masks, so a model is only scored where ground truth actually exists.

2,186
Contracts, each a unique runtime-bytecode fingerprint.
10
Evaluated SWC classes: 101, 103, 104, 107, 113, 114, 115, 120, 128, 135.
1,749 / 219 / 218
Train, validation, and test contracts (80/10/10, multi-label stratified).
1,814 / 363 / 9
CGT-only, DAppSCAN-only, and shared contracts.

Every contract ships as a serialized CFG/DFG graph tensor under data/curated/graphs/, with opcode, TF-IDF, and expert-pattern feature tables under data/features/ and fixed splits under data/splits/main_benchmark/. A machine-readable summary sits in benchmark/clean_default_summary.json, and python scripts/verify_data.py re-checks the counts, split disjointness, and file alignment on demand.

Headline Results

Macro-F1 on the held-out test split, averaged over five seeds, with per-class thresholds tuned on validation only. Running the full sweep regenerates the result files locally under reports/phase7_balanced/.

Detector Type Macro-F1
XGBoost (tuned, enriched features) Tree ensemble 0.805
Random Forest Tree ensemble 0.802
HARDENv2-Graph Heterogeneous graph transformer 0.641
Mythril v0.24.8 Symbolic execution 0.396

The paper reads these numbers as a statement about evaluation protocol as much as about models. With masked labels, fixed splits, and validation-only threshold tuning, feature-based tree ensembles set a strong bar that graph models must be measured against, and the study quantifies that gap with paired permutation tests.

Repository Guide

Path Contents
data/ The benchmark itself: graph tensors, splits, feature tables, and ten synthetic e-government contracts used in the paper's case study.
benchmark/ Benchmark summary, label conventions, and the per-contract identifier manifest for rebuilding bytecode from the upstream sources.
src/ Curation, graph lifting, feature extraction, models, training, and evaluation code.
configs/ Experiment configurations; phase7_balanced.yaml defines the study reported in the paper.
scripts/ Data integrity checks, bytecode reconstruction, manifest generation, and result aggregation.
docs/ARTIFACT.md A guide to reproducing the study's numbers from a fresh clone.

Provenance and Licensing

The release has two layers. Everything the project authored (graph tensors, features, labels, masks, splits) is committed in the repository under CC BY 4.0, with code under MIT. Raw contract bytecode is deliberately absent from every committed file, because DAppSCAN ships no license. In its place the repository publishes a per-contract identifier manifest and a reconstruction script that rebuilds all 2,186 contracts bit-for-bit from the upstream CGT and DAppSCAN checkouts, verifying each against its canonical fingerprint. 

git clone https://github.com/gsalzer/CGT        data/raw/cgt-main
git clone https://github.com/InPlusLab/DAppSCAN  data/raw/dappscan

python scripts/reconstruct_bytecode.py \
    --manifest benchmark/contract_identifiers.csv \
    --cgt-root data/raw/cgt-main \
    --dappscan-root data/raw/dappscan \
    --out data/reconstructed
# a full run reports: 2186/2186 verified
